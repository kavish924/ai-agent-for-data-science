# Spec 08 — Report Generation & Deliverables

> **Status:** Draft v0.1 · **Source:** PRD §6.8, §6.9 · **Milestone:** M6 · **Agents:** Narrator (LLM) + Reporter (deterministic)

## Purpose

Assemble the complete process report and deliver the two required files: the cleaned
dataset and the HTML report — with the LLM narrating findings from computed numbers only.

## User Story

> As a user, I want to download my cleaned data and a report that explains everything
> that was done and found, so I can reuse the results and defend every change.

## Requirements

| ID | Requirement |
|---|---|
| FR-RP-01 | `report.html` contains, in order: ① dataset snapshot (before/after shape & types), ② issues found, ③ cleaning plan & actions with rationale, approval status, and per-step before/after counts, ④ before-vs-after comparison, ⑤ charts, ⑥ ML analysis (problem type, baseline table), ⑦ narrated summary. |
| FR-RP-08 | Every section renders even when sparse (e.g., "no duplicates found"), so the report structure is stable. |
| FR-RP-02 | All **numbers** in the report are inserted from stored artifacts (profile, execution log, model runs) by the Reporter — never generated by the LLM. |
| FR-RP-03 | Narration is produced by the Narrator from **computed numbers only** (profile deltas, execution summary, model comparison); the Narrator cannot introduce figures. |
| FR-RP-04 | If narration fails, a deterministic template summary is used and the report still completes. |
| FR-RP-05 | The cleaned dataset `cleaned_<original_name>.csv` (Spec 05 output) is offered for download alongside `report.html`. |
| FR-RP-06 | Optional extras: `.zip` bundle (cleaned CSV + report + optionally charts and a reproducible Python script of executed steps). |
| FR-RP-07 | Report is available at `GET /sessions/{id}/report` once state = `reported`; earlier requests return `404` with current status. |
| FR-RP-09 | The report footer records tool versions (pandas/sklearn/matplotlib) and the plan `schema` version — reproducibility metadata (PRD §7). |
| FR-RP-10 | PDF export is a stretch goal; v1 is HTML-only. |

## Interfaces

- **Input:** `profile.json`, `plan.json`, `execution_log.json`, `charts/` + manifest,
  `model_runs.json`, `narration.json`
- **Output:** `report.html` (+ optional `bundle.zip`); served by `GET /sessions/{id}/report`
- **LLM:** Narrator only — bounded by the numbers-only gate (`design.md` §5.2, D8)

## Acceptance Criteria

- **AC-1** Given a fully processed Titanic session, when the report is fetched, then
  all seven sections appear in the specified order.
- **AC-2** Given the execution log says `impute(Age, median)`, then the report shows the
  step with its rationale, approval status, and null count before/after — values matching
  `execution_log.json` exactly.
- **AC-3** Given a mocked Narrator, then no number in the report differs from stored
  artifacts (spot-check: null counts, row counts, CV means are artifact-sourced).
- **AC-4** Given narration failure, then the report completes with the template summary
  and no error is surfaced to the download flow.
- **AC-5** Given state `modeled` (not yet `reported`), then `GET /report` returns `404`
  with the current status payload.
- **AC-6** Given any completed session, then the zip bundle contains both deliverables
  and opens cleanly.
- **AC-7** Given a session where the user disabled all steps, then sections render with
  "no changes applied" content (AC-08 stability).

## Dependencies

- Requires artifacts from Specs 02, 03/04 (plan + approvals), 05, 06, 07. Narration
  depends on the LLM being configured (Spec 03's client); failure falls back per FR-RP-04.

## Test Plan

- **Unit:** section renderers with sparse/empty inputs; version footer; zip builder.
- **Integration (LLM mocked):** full report from fixture artifacts; 404-before-ready;
  narration-failure fallback; artifact-number consistency assertions (AC-3).

## Out of Scope

- PDF (stretch), editable/annotated reports, multi-session comparison reports,
  hosting/sharing of reports (PRD §13.4 deployment question — local file download in v1).
